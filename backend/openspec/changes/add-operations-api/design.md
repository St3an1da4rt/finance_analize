## Context

Приложение — FastAPI + SQLAlchemy 2 + Pydantic 2. Пакеты `routes`, `schemas`, `models`, `database`, `config` созданы, но пусты. Аутентификации пока нет. Пользовательские сценарии: загрузка изображения, загрузка голосового, получение операций постранично, проставление групп операций (перевод, зарплата и др.).

## Goals / Non-Goals

**Goals:**
- Три отдельные HTTP-ручки: `POST /images`, `POST /audio`, `GET /operations`.
- Валидация типа и размера загружаемых файлов.
- Хранение операций вместе с группой (category) и статусом обработки.

**Non-Goals:**
- Распознавание изображений/речи и автоматическая категоризация (следующее изменение).
- Аутентификация и мультипользовательность.
- Ручное редактирование группы операции (отдельная ручка позже).
- Облачное хранилище (S3 и т.п.).

## Decisions

- **Загрузка через `multipart/form-data` и `UploadFile`** (а не base64 в JSON): нет раздувания на 33%, стриминг на диск. Требует `python-multipart`.
- **Два отдельных роутера** (`images`, `audio`) вместо одной универсальной ручки: разные допустимые MIME-типы и лимиты размера, соответствует требованию отдельных ручек.
- **Файлы на локальном диске**, путь `UPLOAD_DIR` в конфиге; имя файла — UUID + расширение, оригинальное имя не используется в пути (защита от path traversal). В БД хранится относительный путь. Альтернатива — BLOB в БД: отвергнута из-за размера БД.
- **Операция создаётся сразу при загрузке** со `status=pending`, `amount`/`description` = NULL до распознавания. Ручка возвращает `201` и созданную операцию. Альтернатива — отдельная таблица файлов: избыточно на данном этапе.
- **Группа — enum `Category`**: `transfer`, `salary`, `other`, плюс `uncategorized` по умолчанию; список расширяется миграцией/enum-ом. Хранится как строка в БД.
- **Пагинация `limit`/`offset`**: `limit` по умолчанию 20, максимум 100; сортировка по `created_at DESC, id DESC` для стабильного порядка. Ответ: `{items, total, limit, offset}`. Альтернатива — cursor-пагинация: сложнее, не нужна при малых объёмах.
- **Валидация**: тип проверяется по `content_type`; размер — счётом байт при чтении чанками с обрывом (`413`). Лимиты в конфиге (изображение 10 МБ, аудио 25 МБ по умолчанию).
- **БД**: SQLAlchemy 2, по умолчанию SQLite через `DATABASE_URL`; таблицы создаются при старте (миграции Alembic — позже).

## Risks / Trade-offs

- [Доверие `content_type` от клиента] → дополнительно проверять сигнатуру файла (magic bytes) для изображений; для аудио — по расширению/типу на первом этапе.
- [Диск заполняется, файлы без операции при сбое] → при ошибке записи в БД удалять сохранённый файл.
- [Нет аутентификации, ручки открыты] → зафиксировано как non-goal; добавить до выхода в продакшен.
- [offset-пагинация нестабильна при вставках] → детерминированная сортировка; приемлемо на данном этапе.
